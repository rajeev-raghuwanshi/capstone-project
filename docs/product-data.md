### Generated persistence contract

- File: `data/products.json` (json-array).
- Missing file: `initialize-empty-array`.
- Invalid data: `raise-storage-error-and-preserve-file` using `ProductStorageError`.
- In-process operation serialization: enabled.
- Write strategy: `same-directory-temporary-file-then-rename`.
- Multiple-process coordination: not provided.

Product records are stored in `data/products.json` as a JSON array. The file is resolved under the project directory. If it does not exist when the application first reads the catalogue, the repository creates the directory and initializes the file to an empty array.

## Stored Record

```json
{
  "id": "6e7c8a73-2fe3-4a44-8e73-29fdc860e42b",
  "name": "Notebook",
  "pricePaise": "1250",
  "category": "Stationery"
}
```

| Field | Stored format | Rules |
| --- | --- | --- |
| `id` | UUID v4 string | Generated by the application, unique within the product array, and unchanged by updates. It is not accepted from form input. |
| `name` | String | Required; trimmed; must not be empty. No maximum length is enforced. |
| `pricePaise` | Decimal string containing integer paise | Required and positive. For example, `"1250"` represents INR 12.50. A string is used to preserve exact paise values without a JavaScript safe-integer ceiling. |
| `description` | Optional string | Trimmed. Omitted when blank. No maximum length is enforced. |
| `category` | Optional string | Free-form and trimmed. Omitted when blank. No category list is enforced. |
| `imageUrl` | Optional string | Trimmed and omitted when blank. No URL-format validation is performed. The website displays its value as escaped text rather than loading it as an image. |

Blank optional fields are omitted from persisted records. If an optional field is present in the JSON file, it must be a non-empty trimmed string. Records with fields outside this schema, invalid field values, or duplicate IDs are treated as invalid product data.

## Form Price Validation

The form accepts a decimal INR value, which is converted exactly to the `pricePaise` string before persistence. Input is trimmed and must use decimal notation with no more than two fractional digits. A leading plus sign and a leading decimal point are accepted (for example, `+12.50` and `.50`). Zero, negative values, exponent notation, and values with more than two fractional digits are rejected. No maximum amount is imposed by the validator.

## Persistence and Errors

- Repository operations use `data/products.json`; callers do not supply the storage path through a request.
- Missing data initializes to an empty product list.
- Reads, mutations, and writes are serialized within the application process.
- Updates write a temporary file in the same directory and rename it into place after the write completes.
- Malformed JSON, a non-array root, invalid product records, duplicate IDs, and unreadable files produce a storage error. The server remains running, requests that need storage return a generic `500` page, diagnostic details are logged server-side, and the existing file is not silently replaced.
- Failed writes do not report a successful change; a failed temporary-file replacement leaves the existing data file intact.
- The repository does not coordinate multiple Node processes. Multi-process writes are outside the initial prototype's scope.
